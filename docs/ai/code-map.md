## Project config (repo root)
- `FinTrack.xcodeproj/project.pbxproj` — ONE target `FinTrack` (iOS app), `PBXFileSystemSynchronizedRootGroup` on `FinTrack/` ⇒ every file under `FinTrack/` is compiled/bundled automatically; nothing else is. No SPM packages, no test target. Deployment iOS 26.5, `SWIFT_VERSION = 5.0`, `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, `SWIFT_APPROACHABLE_CONCURRENCY = YES`, member-import-visibility upcoming feature. Bundle id `com.mohd.fintrackpro.FinTrack`. Exported UTType `com.mohd.fintrackpro.fintrack` (`.fintrack` backup files). Usage strings: camera, Face ID, location, microphone, photos, speech. `CODE_SIGN_ENTITLEMENTS` absent.
- `FinTrack-Info.plist` — merged with generated plist. Holds a Gmail OAuth client ID (public client id; don't copy into docs), BG task id `com.fintrack.email-sync`, background mode `fetch`. File sharing deliberately off.
- `FinTrack/FinTrack.entitlements` — declares App Group `group.com.fintrack.shared` but is **not referenced by the build** (inert; App Groups need a paid account). Its comment about the SMS queue "falling back" is stale wording: all in-app queues (SMS, Apple Pay, Siri log) use `.standard`.
- `FinTrack/Assets.xcassets` — AppIcon (single 1024 `logo.png`, dark/tinted slots empty), AccentColor (no value set).
- `.gitignore` — Xcode user state, build products, `.DS_Store`.
- `README.md` — title only. `docs/privacy-policy.html` — public privacy policy (claims: no server, on-device parsing, Gmail read-only, optional backups to iCloud/Drive/email). `docs/DISABLED_FEATURES.md` — dev-only list mirroring `DisableableFeature.disabled`; must be kept in sync.
- `FinTrackWidget/`, `FinTrackWatch/` — Swift sources **outside any build target** (never compiled).

## App
- `App/FinTrackApp.swift` — `@main FinTrackApp`: builds `ModelContainer` from `Schema(AppSchema.modelTypes)`; **schema wipe** when UserDefaults `fintrack_schema_version` ≠ `currentSchemaVersion` ("v28") deletes `Application Support/default.store*` and all pending/delivered notifications; container failure ⇒ `fatalError`. `init` registers BG email sync. Injects `AppState`, `CurrencyService`, `CryptoPriceService`, `StockPriceService` into environment; launch `.task` fetches FX + crypto, requests notification permission. Also defines `AppState` (`@Observable @MainActor`: `isLocked`, `hasCompletedOnboarding`, `selectedTab`, `showingAddTransaction`, `baseCurrency`, `tabBarCollapsed`, `popToRootTick`; persists `has_completed_onboarding`/`base_currency` in UserDefaults) and `AppTab` (dashboard/transactions/add/budget/accounts/reports; `.reports` has no iPhone tab, only iPad detail).
- `App/RootView.swift` — root router: snapshot-restore screen (only when `has_completed_onboarding` false AND `LocalBackupService.hasDeviceSnapshot`) → `OnboardingView` → `LockScreenView` → iPad `NavigationSplitView` / `MainTabView`. **Lifecycle hub**: on appear and on every `.active`: `ensureDefaults` (inserts `UserProfile`/`AppSettings` if missing), lock if biometrics/PIN, `processRecurringTransactions`, `processScheduledTransactions`, `processBillAlerts`, `processIncomeAlerts`, `processDebtAlerts`, drains (`drainPendingIntentQueue` Siri/Watch, `drainPendingSMSTexts`, `drainPendingApplePay`, `drainPendingNavigation`), Drive/email backup triggers; `.active` also runs `EmailSyncService.runSyncPass`; `.background` schedules BG refresh + locks. `.task`: starts email auto-sync, `LocalBackupService.startObservingChanges`, Drive/email auto-backup, crypto/stock price refresh. Badge = pending review count. On appear also mirrors `AppSettings` into `NotificationService.apply(settings:)` and the `Calendar.firstWeekdayKey` default. `processRecurringTransactions` advances rules with `RecurringRule.occurrence(after:)`, stops past `endDate`, and posts transfers to both accounts. Spotlight continuation only switches tab (doesn't open the record). Also holds `MainTabView` (TabView with hidden native bar + `CustomTabBar`), `TabBarScrollCollapseModifier`/`collapsesTabBarOnScroll()`, `CustomTabBar` (calls `.glassEffect` directly, bypassing `ftGlass`). Bill auto-pay checks fetch the last 90 days on demand (no root-level ledger `@Query`). Applies `.dynamicTypeSize(...accessibility2)`. `CustomTabBar`: 44pt add target, 10pt labels, large-content viewer.

## Models (`Core/Models/`)
Conventions: older models store enums directly as attributes (`Transaction`, `Account`, `BNPLPlan`, `Budget`); newer ones store `*Raw: String` + computed accessor (safe in `#Predicate`). Embedded arrays = JSON `Data` + computed accessor. Enum rawValues are persisted — renaming a case or rawValue corrupts/defaults existing rows. Loose cross-links are UUID/String ids, not relationships.
- `AppSchema.swift` — `AppSchema.modelTypes`: the single list (53 types) used by `FinTrackApp` (Schema) and `DataResetService` (wipe). New `@Model` ⇒ add here + bump `currentSchemaVersion` (wipes data — ask user first).
- `Transaction.swift` — `@Model Transaction`: amount/currency/`amountInBaseCurrency` (⚠ init defaults it to `amount` when nil ⇒ wrong for foreign currency; callers pass it), `type`, `category`, `paymentMethod`, `subtype` (enums stored directly), pending/scheduled flags, `splitItems: [SplitItem]`, receipt image (externalStorage), GPS, cheque fields, tax flags. Relationships: `account` (inverse of `Account.transactions`), `toAccount`, `linkedLoan`, `linkedBNPL`, `documents` (cascade). Loose UUID links: salary record/payment, money lent/borrowed, debt repayment, bill, custom category, loyalty program. `spendingPairs` = category/base-amount pairs (splits scaled by base rate) for aggregation; excludes pending/scheduled and `isPrincipalMovement` (person-to-person lending/borrowing and repayments — skipped by income/expense totals app-wide). Also `TransactionType`, `TransactionCategory` (rawValues persisted, icon/color), `PaymentMethod`, `TransactionSubtype` (`isSpendingReduction`), `RecurringRule` (frequency, `endDate`, `maxOccurrences` (never set by UI); `occurrence(after:)` = next date for the frequency), `RecurringFrequency`.
- `Account.swift` — `@Model Account`: `balance` (stored, mutated by services/views), `initialBalance`, bank/custom bank, flags `isDefault/isArchived/isHidden/isBusiness/isLinked`, wallet provider, retirement type, minimum-balance alert. ⚠ `transactions` relationship is `.cascade` ⇒ deleting an account deletes its transaction history. `AccountType` (`isLiability` only for `.creditCard`), `WalletProvider`.
- `AssetModels.swift` — `RealEstateProperty` (equity = value × ownership − full mortgage balance), `Vehicle` (straight-line/declining depreciation or manual value), `PersonalAsset`, `DigitalAsset` (default currency USD), `NetWorthSnapshot` (breakdown JSON, externalStorage), `NetWorthMilestone`. All `*Raw` enum strings.
- `BNPL.swift` — `@Model BNPLPlan` (provider enum stored directly; `remainingInstallments` = total − paid, can go negative if over-paid; `isPaymentDueSoon` ≤3 days). `applyInstallmentPayment()`/`reverseInstallmentPayment()` — invariant: each posted expense tx with `linkedBNPL` = one paid installment (used by AddTransaction, list delete, BNPL sheets, email approval). `BNPLProvider` tabby/tamara/postpay/spotii/custom.
- `Bill.swift` — `@Model Bill`: `*Raw` strings, `BillingCycle` (interval, `monthlyFactor`), `BillCategory.transactionCategory`, `priceHistory` JSON (`previousAmount` = last entry), alert-state fields used by `BillService`, `isOverdue = nextDueDate < now`.
- `Budget.swift` — `@Model Budget` (category/period enums stored directly, rollover, shared, `notifiedThresholds`/`notifiedMonth` for alert dedup). Stored `spent` is never updated (always 0) — kept for schema compatibility; the `remaining/progress` accessors built on it were removed (`isNearLimit` computes its ratio inline); spend comes from `BudgetService.spending`. `isInEffect(during:)` = active and not past `endDate`. `@Model SavingsGoal` (`goalTypeRaw`, auto-contribution amount/frequency/next date, template fields, computed progress/remaining/projected completion), `GoalContributionFrequency`, `@Model BudgetEnvelope`, `@Model BudgetTemplate` (`items: [TemplateItem]`, `TemplateSeason`). `BudgetRecommendationRecord` struct unused.
- `BusinessModels.swift` — `ClientProfile`, `BusinessInvoice` (line items + payments as JSON; `recordPayment` sets paid/partiallyPaid; `isOverdue` = past due and not paid/cancelled, so a past-due *draft* counts as overdue), `MileageTrip` (`reimbursementAmount = km × rate`, default 0.29), `BusinessProject` (`ProjectStatus` is defined in `IncomeModels.swift`; `tagKey` slug from name at init only). Enums `BusinessInvoiceStatus`, `ClientStatus`, `MileageVehicleType`, `MileagePurpose`; structs `InvoiceLineItem` (default VAT 5%), `InvoicePaymentRecord`. `BusinessInvoice.totalVAT/totalAmount` honour `vatIncluded`. Invoices link clients by `clientId` string.
- `CategorizationRule.swift` — `@Model CategorizationRule` (priority asc, `RuleConditionType` merchantEquals/Contains, titleContains/Regex, amountRange, currency; target built-in or custom category; `autoTags`). `matches(title:merchant:amount:currency:)` is the evaluator (regex compiled per call).
- `CreditCard.swift` — `@Model CreditCard` (limit, outstanding, min payment, due date, statement day). Separate from `Account` of type `.creditCard` — two parallel credit-card representations (see services for which screens use which).
- `CustomCategory.swift` — `@Model CustomCategory`: user categories with `parent` (nullify) / `children` (**cascade** — deleting a parent deletes its subcategories); `transactionTypeFilter` "any|expense|income"; `fullPath`, `depth`; palette + icon catalog. Transactions reference it by loose `customCategoryID`/`customCategory` name, so deletion leaves dangling refs.
- `DebtModels.swift` — `@Model MoneyLent` / `MoneyBorrowed` (person-to-person debts; `repayments: [RepaymentRecord]` JSON, externalStorage). Two status sources: stored `status` (incl. `.writtenOff`) and derived `computedStatus` (repaid/overdue/partial/active, never written back). `PersonalDebtStatus`.
- `DisableableFeature.swift` — developer-only kill switch for Settings modules. `disabled` set (currently: collaborativePlanner, insuranceOptimizer, remittanceTracker, taxManagement, businessFreelancer, auditLog, googleDriveBackup, pdfStatementImport, twoFactorAuth) — keep in sync with `docs/DISABLED_FEATURES.md`. `category` decides where the row lives (premium grid / top-level section / nested call-site check).
- `DocumentAttachment.swift` — `@Model DocumentAttachment` (file `data` externalStorage, mime type, inverse `transaction`).
- `EmailImportModels.swift` — `EmailProvider` (gmail/outlook = OAuth REST; icloud/imap = app password over IMAP). `@Model EmailAccount` (metadata only; tokens in Keychain at `tokenKeychainKey`; `seenMessageIds` JSON set = re-import guard — kept by Clear All Data). `@Model BankEmailRule` (bank sender/domain/subject/keywords; `senderEmail` prefixed `"sms:<slug>"` = SMS bank rule; `linkedAccountId` posting override; `autoApprove`/`confidenceThreshold` unused — every import waits for review). `@Model PendingEmailTransaction` = **the review-queue item for all automated channels** (parsed fields, short snippet only, confidence/explanation, suspicious flag, fingerprint + duplicate flags, status, matched rule/account, `bnplSelectionRaw`). BNPL encoding in `bnplSelectionRaw`: nil = undecided (blocks approval), `"none"`, `"<uuid>"`, or `"<uuid>:<amt>,<uuid>:<amt>"`; `bnplAllocations`, `setBNPLAllocations`, `bnplNeedsAmountFix`. `isBNPLMerchant` = substring match on `bnplKeywords` (⚠ "valu" also matches e.g. "Value…" merchants ⇒ approval blocked until a BNPL choice).
- `FamilyModels.swift` — local-only family records (no sync/sharing backend): `FamilyGroup` (members as JSON `FamilyMemberData` with per-resource permission records), `ChildProfile` (allowance payments JSON; `addPayment` adds 10% of each *confirmed* allowance to `currentSavings` (disclosed under the "confirmed" toggle in `RecordAllowancePaymentSheet`); month = 30 days), `SharedFamilyGoal` (contributions JSON, presets). Enums `FamilyPermissionLevel`, `FamilyMemberRole`, `AllowanceFrequency`.
- `GiftCard.swift` — `@Model GiftCard` (balance/initialBalance, expiry). Stores `cardNumber` and `pinCode` as plain model attributes (sensitive data in the store and in backups).
- `GoldHolding.swift` — `@Model GoldHolding` (metal/form/unit enums stored directly; weight always grams; P/L computed). `PreciousMetal` (hardcoded `referencePriceUSD`), `GoldForm`. `WeightUnit` lives in `InvestmentModels.swift`.
- `ImportModels.swift` — `@Model ImportedFile` (statement import history; `parsedItems: [ParsedTransactionItem]` JSON). `ImportFileType` pdf/ofx/qif/qfx/csv, `ImportStatus`.
- `IncomeModels.swift` — `@Model SalaryRecord` (expected amount/day; `payments: [SalaryPayment]` JSON; ⚠ `nextExpectedDate` assumes monthly regardless of `paymentFrequency`), `@Model FreelanceProject` (`invoices: [FreelanceInvoice]` JSON — a second invoice system separate from `BusinessInvoice`), `@Model RentalProperty` (occupancy periods + rent payments JSON). Enums `PaymentFrequency`, `SalaryPaymentStatus`, `ProjectStatus` (also used by `BusinessProject`), `InvoiceStatus`, `RentalPropertyType`.
- `InsurancePolicy.swift` — `@Model InsurancePolicy` (`typeRaw`, `premiumFrequencyRaw`; `annualPremium`, renewal countdown). Enums `InsurancePolicyType`, `PremiumFrequency`.
- `Investment.swift` — `@Model Investment` (type enum stored directly; default currency USD; `lots: [PurchaseLot]`, `sales: [SaleRecord]` JSON externalStorage; `realizedPnL` running total), `@Model CryptoHolding` (same shape + wallet address), `@Model Dividend` (linked by `investmentId` UUID; net = amount − withholding). `InvestmentType`.
- `InvestmentModels.swift` — non-persisted types: `PurchaseLot`, `SaleRecord` (optional `acquiredDate`; `isLongTerm` = acquired → sale ≥12 months, false when unknown), `CostBasisMethod`, `WeightUnit` (g/kg/tola 11.6638/troy oz 31.1035), `ContributionFrequency`, `BenchmarkType` (hardcoded annual returns 2019–2024; missing years assume 8%), `ProjectionPoint`, `MonteCarloResult`, `AllocationSlice`, `CapitalGainsSummary`.
- `Loan.swift` — `@Model Loan` (`loanType` stored directly; `totalInstallments` = months start→end; `amortizationSchedule` capped at 600 rows). `recordPayment(amountInLoanCurrency:)` = **single rule** for applying a repayment (interest on outstanding, rest to principal, +1 installment, advance due date or deactivate) — shared by `AccountDetailView` and `EmailSyncService.approveToLedger`; caller must convert currency first. Note: counts one installment per payment regardless of size, and deactivates when the count is reached even if balance remains. `LoanType`, `AmortizationEntry`.
- `LoyaltyProgram.swift` — `@Model LoyaltyProgram` (`programType` stored directly; `estimatedValue = points × valuePerUnit`; expiring ≤60 days). `LoyaltyProgramType` (UAE airlines/retail/hotels/banks).
- `PremiumModels.swift` — `@Model RetirementPlan` (FV projection + UAE end-of-service gratuity 21/30 days per year; 25-year annuity nest egg), `@Model LifeEventPlan` (`eventTypeRaw`, checklist JSON), `@Model AdvisorAccess` (local-only: random 8-char `accessCode`, permission flags, notes JSON — there is no backend; feature disabled). Enums `LifeEventType` (default budgets + checklists), `AdvisorRole`.
- `RemittanceRecord.swift` — `@Model RemittanceRecord` (`providerRaw`; sent/received/rate/fee; `effectiveRate`, `feePercent`). `RemittanceProvider`.
- `SecurityModels.swift` — `@Model AuditLogEntry` (append-only security/event log; `eventTypeRaw`, `deviceName`). `AuditEventType` (`isSecurityEvent`).
- `TaxModels.swift` — `@Model TaxRecord` (VAT entry, rate default 5), `@Model TaxDocument` (file externalStorage, loose links to transaction/VAT record), `@Model ZakatRecord` (asset/deduction inputs in AED, nisab gold 87.48 g / silver 612.36 g with stored per-gram prices, 2.5% or manual override), `@Model TaxConfiguration` (country presets AE/SA/GB/US/AU with brackets JSON). ⚠ `estimatedIncomeTax` subtracts `personalAllowance` *and* applies brackets that already contain the 0% allowance band ⇒ double-counts the allowance for GB/AU (under-estimates tax). Feature currently disabled.
- `UserProfile.swift` — `@Model UserProfile` (name, base currency, `language: AppLanguage` stored directly, goals, `hasCompletedOnboarding`), `@Model AppSettings` = **all user preferences**: security (`useBiometrics` default true, `usePIN`, `pinHash`, `autoLockMinutes`, `twoFactorEnabled`/`twoFactorSecret`, `auditLogEnabled`), notification toggles/thresholds/digest schedule, appearance (`theme: AppTheme` stored directly, accent, OLED, high contrast), `cloudSyncEnabled`, `backupWifiOnly`, fiscal-year start, first weekday, `dashboardHiddenWidgets` CSV. Sensitive: `pinHash` (salted, `PINService`) and `twoFactorSecret` live in the store and backups. `AppLanguage` (en/ar, RTL), `AppTheme`.

## Services (`Core/Services/`)
Mostly `final class X { static let shared }` singletons, MainActor by default (build setting). Pure helpers take arrays of models and return value structs; persistence-touching ones take a `ModelContext`.
- `AIAnalyticsService.swift` — pure, local heuristics (no ML, no network, no persistence): `computeHealthScore` (savings rate 30% / emergency fund 25% / debt-to-income 25% / investment count 20% → grade), `detectAnomalies` (category z-score > 2 vs last 6 months, large tx > 3× avg and > 500, new merchant > 200), `predictBalance` (30-day: avg daily spend + bills due + recurring guesses), `computeSpendingPatterns`, `findSavingsOpportunities`, `generateCoachingInsights` (rotates by week number), `generateBillNegotiationTips`, `analyzeESG` (category→rating + carbon factor), `runDigitalTwin` (snapshot net worth floored at 50% of current), `monthlyAverages`. Defines the result structs (`HealthScoreResult`, `SpendingAnomaly`, `BalanceForecast`, `SavingsOpportunity`, `CoachingInsight`, `BillNegotiationTip`, `ESGResult`, `DigitalTwin*`). Account/loan balances are converted to the base currency; income/expense filters skip `isPrincipalMovement`.
- `AICategorizationService.swift` — `predictCategory(for:merchant:amount:type:rules:)` order: enabled `CategorizationRule`s by priority (called with `currency: ""`, so currency rules never match here) → `CategoryLearningService` learned merchant (0.92) → keyword substring table (0.75) → fallback (`.salary` for income, `.other`). ⚠ keyword table is a `Dictionary`, so when several categories match, the winner depends on per-launch hash order; and very short keywords match inside words (`"du"` ⊂ "dubai" ⇒ utilities, also `"bp"`, `"eat"`, `"bag"`, `"lab"`, `"total"`, `"return"`, `"apple"`). Also `detectRecurring` (title prefix + integer amount, ≥2 occurrences), `detectDuplicates`, `generateInsights` (month-over-month ±15%, savings rate), `forecastNextMonth`. Defines `CategoryPrediction`, `FinancialInsight`. `NaturalLanguage` imported but unused.
- `ApplePayIngestService.swift` — `@MainActor enum`. `ingest(amount:merchant:currency:date:walletCategory:card:isRefund:context:)` turns Wallet/Shortcuts structured fields into a `ParsedBankEmail` (confidence 0.95, currency validated by `ISO4217` else base currency, card last-4 from card name) → `ImportFiler.file(channel: .applePay, categoryOverride: mappedCategory(...))` → saves. Never posts to the ledger directly. Received log: last 20 outcomes in `UserDefaults.standard` key `ft_applepay_received_v1` (`succeeded` compares the outcome text to the literal `"Added to the review queue"` — must match `ImportFiler`'s summary).
- `BackupEncryptionService.swift` — `nonisolated enum`. Every `.fintrack` backup = `"FTBK1"` magic + 16-byte salt + AES-GCM combined box; key = PBKDF2-HMAC-SHA256 (100k iterations, hand-written over CryptoKit HMAC, run in `Task.detached`) of a random 256-bit device key stored in Keychain `ft_backup_encryption_key` via `KeychainStore` (defined in `EmailSyncService.swift`, `…AfterFirstUnlockThisDeviceOnly`). `encryptIfEnabled` (always encrypts), `decryptIfNeeded` (plain legacy files pass through). By design a backup can only be restored on the device whose Keychain holds the key (copy says so); `encryptionKey()` throws if a new key can't be saved.
- `BankEmailParser.swift` — regex extraction for bank notification emails. `uaeBanks` sender-domain whitelist (18 banks); `isLikelyBankTransactionEmail` (marketing/OTP subjects rejected); `gmailSenderQuery(extraSenders:)` (whitelist + rule senders, `newer_than:60d`); `parse(sender:subject:body:receivedAt:)` → `ParsedBankEmail?` (amount+currency required; confidence additive per field; suspicious if > 100k or no merchant and no direction keyword, capped 0.55). Static extractors `extractAmount/Direction/Merchant/CardLast4/Balance/Reference/Date`, `normalize(body:)` (HTML strip), `fingerprint(...)` = `ref:<reference>` or `fp:<cur>:<amt>:<UTC day>:<last4>:<merchant token>` (shared dedup identity across channels). Notes: credit keywords (incl. generic `"received"`) are tested before debit ones; the fingerprint day is the UTC day (UAE 00:00–04:00 local falls on the previous day); dates parsed in device time zone. Defines `ParsedBankEmail`, `UAEBankProfile`.
- `BillService.swift` — `recordPayment(bill:amount:date:)` (logs old amount to `priceHistory` if changed, sets last paid, resets alert flags, advances `nextDueDate` one cycle, reschedules), `scheduleReminders`/`cancelReminders` (ids `bill_<uuid>_<days>`, `bill_overdue_<uuid>`, `bill_autopay_<uuid>`; prefix added in `NotificationService.scheduleBillReminder`), `scheduleAllReminders`, `isAutoPayMissed` (no expense whose title/merchant matches the bill name/provider in [due−2d, due+window]), `analyzeWaste` (subscriptions: days since last matching tx → confidence), `checkAllAlerts` (late once per due day via `notifiedOverdueDateRaw`; autopay once via `notifiedAutoPayMissed`; price change), `detectPriceChange` (amount vs last `priceHistory` entry). Called from `RootView.processBillAlerts` (launch + every `.active`) and `BillsView.onAppear`. Price-change alert fires once per new price (UserDefaults `ft_bill_price_alert_<id>`); all bill notifications go through `NotificationService.deliver` (honours settings).
- `BiometricService.swift` — `LAContext` wrapper: `biometricType/Name/Icon`, `isAvailable`, `authenticate(reason:)` (biometrics only, cancel title "Use PIN"), `authenticateWithBiometricsOrPIN` (device passcode fallback).
- `BudgetService.swift` — **budget↔transaction matching rule** (shared by BudgetView and others): `autoKeyword(from:)` strips generic words from the budget name; `effectiveKeyword(for:allBudgets:)` = explicit `merchantFilter`, else auto keyword when sibling budgets share the category or the keyword has ≥2 words; `matchingBudget(...)` (only budgets `isInEffect`); `spending(for:allBudgets:transactions:in:)` (always a calendar *month*; keyword-filtered `spendingPairs` of the budget's category; if 0, falls back to keyword match across **all** categories). `forecastEndOfMonth` (pace blended with 3-month history), `checkAndSendAlerts` (75/90/100% once per month via `notifiedThresholds`/`notifiedMonth`; ids `budget_<uuid>_<pct>`), `processRollovers` (monthly rollover budgets: `rolloverAmount` = last month's unused, recomputed not accumulated), `generateRecommendations` (create/increase/decrease/anomaly/savings, base currency; increase/decrease carry `budgetId` so BudgetView's Apply updates that budget), `builtInTemplates` (Ramadan/Eid/Summer). Budget limits are converted from `budget.currency` to base via `CurrencyService`.
- `CSVImportService.swift` — `parseCSV(data:delimiter:)` (UTF-8 → Latin-1 fallback, delimiter auto-detected from the header line), `detectDateFormat(samples:)`, `suggestMapping(for:)` (header keyword match), `mapRows(_:mapping:existingTransactions:rules:)` → `[CSVImportRow]` (category always from `AICategorizationService.predictCategory` — the mapped `categoryColumn` is ignored; duplicate key = title + integer amount + day). Limitations: the file is split on newlines *before* quote handling (quoted multi-line fields break; `""` escapes are dropped); amount cleaning keeps only `0-9 . -` (European `1.234,56` misparses); with separate Debit/Credit columns only one is mapped.

Flow: Shortcuts automation → `LogTransactionFromText` intent → `WidgetDataService.enqueuePendingSMS` (+ `SMSIngestService.recordQueued`) → `RootView.drainPendingSMSTexts` → `SMSIngestService.ingest` → `BankSMSParser.parse` → `ImportFiler.file(channel: .sms)` → review queue.
- `SMSIngestService.swift` — `@MainActor enum`. `ingest(rawText:senderId:receivedAt:queueId:context:) async -> Bool` (user SMS bank rules — `BankEmailRule` with `sms:` sender and sender ids stored in `keywords` — become extra templates; files each parsed result; saves; logs outcome). Received log: last 20 in UserDefaults `ft_sms_received_v1` (`ReceivedSMS` with `waitingOutcome` placeholder replaced in place via `queueId`; `succeeded` matches the `ImportDeduper` summary prefixes), `recordQueued`, `clearReceived`, `senderTag`, `lastImportKey`.
- `BankSMSParser.swift` — `parse(rawText:senderId:userTemplates:) async -> [ParsedBankEmail]`: `TextNormalizer.normalize` → skip OTP/marketing/declined/due-reminder keywords → **template tier** (bank via `BankSMSTemplateStore.identify`, then `BankEmailParser` static extractors; confidence additive, suspicious cap 0.55) → else **on-device model tier** (`FoundationModelsSMSExtractor`, every field checked with `TextNormalizer.isGrounded`; confidence capped 0.85, 0.5 if direction unknown). With no date in the text both tiers use the queued `receivedAt` (passed by `SMSIngestService`).
- `BankSMSTemplateStore.swift` — `BankSMSTemplate` (bankId, bankName, senderIds). `bundled` (11 UAE banks, sender ids are unverified guesses), `active` (bundled + cached remote `ft_sms_bank_templates_v1`), `refreshFromRemote(url:)` (no caller supplies a URL), `identify(senderId:text:extraTemplates:)` (sender substring either direction, else bank name in text — short names like "Liv"/"FAB" also match inside words such as "delivered"/"fabric"), `slug(_:)`.
- `FoundationModelsSMSExtractor.swift` — Apple on-device `LanguageModelSession` with `TransactionExtractionPrompt.text` instructions, guided generation into `SMSExtractionResult`; `isAvailable`, `unavailableReason`.
- `SMSExtractionTypes.swift` — `@Generable` `SMSExtractionResult` / `SMSExtractedTransaction` (fields + `*Evidence` substrings), `SMSTxKind`, `SMSTxDirection`.
- `TransactionExtractionPrompt.swift` — the long system prompt (perspective, evidence/grounding rule, type/direction rules, amount≠balance, currency, number-separator rules incl. 3-decimal currencies, dates, last-4 rules, multi-transaction, confidence, never-do list).
- `TextNormalizer.swift` — `normalize(_:maxCharacters:)` (NFKC, strip bidi/zero-width, fold spaces/separators/any Unicode decimal digits to ASCII, collapse spaces, head+tail truncation at 4000), `decimalValue(in:)` (used by the Apple Pay intent for Wallet's text amount), `foldForComparison`, `isGrounded`. `decimalValue`: a lone separator is the decimal point unless it repeats or is a comma followed by exactly 3 digits ("45.5", "KWD 1.250" read correctly).
- `ISO4217.swift` — `codes`, `isValid`, `minorUnits(for:)`, `usesThreeDecimals`.
